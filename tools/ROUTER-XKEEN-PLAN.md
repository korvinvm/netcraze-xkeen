# XKeen на Netcraze Ultra (NC-1812) — план и что уже разведано

Статус: **ждём сети**. Ноутбук не в той подсети, роутер недоступен.

## Что известно

- Роутер: Netcraze Ultra **NC-1812** (это Keenetic-линейка, прошивка NDMS, не OpenWrt).
- Адрес роутера: `192.168.2.1`, логин `admin`, пароль знает пользователь.
- Подписка VLESS с правилами: `https://sub.conn-liberty.net/...` (полный URL — у пользователя).
- Ориентир: статья Habr 986200 — три режима Direct / Split / Full через XKeen + Xray,
  Full реализован через «Клиент прокси» NDMS → локальный SOCKS5 Xray (например 127.0.0.1:1082).
- Задача: XKeen на стоковой прошивке. **OpenWrt не ставить, прошивку не менять.**

## Почему сейчас не получилось

- Ноутбук в сети `Alina_5G`: `192.168.1.77`, шлюз `192.168.1.1`.
- Роутер — `192.168.2.1`, другая подсеть.
- Запущен VPN-клиент (`happ-default-tun`, `10.6.7.1`): маршрут к `192.168.2.1` уходит в туннель.
  TCP-порт открывается, но ответа нет — классический «VPN съел пакет».
- Видимая Wi-Fi сеть только одна — `Alina_5G`. Роутер либо по кабелю, либо его Wi-Fi выключен.

## Что нужно, чтобы продолжить

1. Ноутбук подключить к сети роутера: кабель в LAN-порт или Wi-Fi этого роутера (IP станет `192.168.2.x`).
2. VPN-клиент (`happ`) выключить на время настройки.
3. Проверить, что флешка (USB-накопитель) воткнута в роутер — Entware живёт на ней.

## Порядок работ (после подключения)

1. **Только чтение:** `show version`, `show system`, `show media`, список интерфейсов,
   есть ли уже Entware (`opkg list-installed | head`), состояние WAN.
2. **Бэкап конфига** (веб-UI → Управление → Конфигурация, скачать `.conf`), записать путь отката.
3. **Entware** штатным компонентом Keenetic на флешку (не прошивка).
4. **XKeen + Xray** из GitHub, конфиг из подписки пользователя.
5. **Политики:** сначала одно тестовое устройство в Split, проверить выход, потом остальные.
   Full — через «Клиент прокси» NDMS на локальный SOCKS5 Xray.
6. После каждого шага проверять, что роутер отвечает и дом живёт.

## Откат

- XKeen: `xkeen -stop` и удаление пакета, Entware снимается штатно.
- Конфиг NDMS — из сохранённого `.conf`.
- WAN, DHCP и прошивка не трогаются вообще.

## Инструменты, которые уже готовы

- `AstrologyBot/tools/router_ssh.py` — SSH к Keenetic с legacy-алгоритмами dropbear
  (пароль передаётся через `ROUTER_PASS`, в файл не пишется). Запускается внутри контейнера,
  потому что в нём есть paramiko: `docker exec -e ROUTER_PASS=... astrology-bot python /tmp/router_ssh.py "show version"`.
